## 1. Что это за проект

**Навигатор ПП РФ №719** — AI-сервис для **Курской торгово-промышленной палаты (ТПП)**.
Помогает предприятиям и экспертам разобраться в требованиях Постановления Правительства РФ №719
о подтверждении производства российской промышленной продукции (критерии локализации, баллы,
документы).

Пользователь — **штатный сотрудник ТПП**, разрабатывает продукт силами Claude Code.
Цель — рабочий прототип для демонстрации руководству.

**Главный принцип продукта:** ИИ выдаёт только **предварительный анализ**, окончательный
вердикт всегда за **экспертом ТПП**. Это снимает опасения руководства про «осторожность с ИИ».

Полный контекст — в [CLAUDE.md](CLAUDE.md). План фаз — в [ROADMAP.md](ROADMAP.md).
Техспек V1 — в [docs/V1_SPEC.md](docs/V1_SPEC.md).

## 2. Краткая история: что уже сделано (движок 0.5.0 ✅ · продукт мини-1.0 ✅ собран)

> Актуальный статус каждой фазы — всегда в [ROADMAP.md](ROADMAP.md) и [CLAUDE.md](CLAUDE.md)
> («Текущий статус»). Ниже — сжатая сводка.

**Где проект сейчас (0.5.0 → цель 1.0):** движок навигатора готов и измерен (recall@1 0.98 с
реранкером; тест-батарея качества ответа P0/P1/P2 закрыта; база 1357 точек / 1347 продуктов / 29
разделов), а поверх него **собран и отполирован продукт мини-1.0** — веб-чат-ассистент эксперта
ТПП (FastAPI + Jinja2 + ванильный JS: вход/роли `user`/`expert`/`admin`, окно чата ChatGPT-стиля
с историей/экспортом, лог диалогов, фидбек, `/admin` с дашбордом; 42 теста + e2e). **Осталось до
1.0: развернуть (docker-compose на РФ-облаке) + приёмка эксперта ≥70%.** Отложено (fast-follow):
стриминг, history-aware мультитёрн, полный корпус Правил реестра.

**Фаза V0 (фундамент) — хронология:**

1. **Концепция и архитектура.** Спроектирован сервис: 3 модуля — Навигатор (V1),
   Валидатор документов (V2), Генератор актов (V3). Выбран RF-доступный стек.
2. **Репозиторий.** Создан git-репо, запушен на GitHub: **https://github.com/pan3v1n/navigator-719**
   Настроен автопуш через `post-commit` hook.
3. **Структура проекта.** Создана: `app/` (core, rag, tools, api, db), `knowledge_base/`,
   `scripts/`, `frontend/`, `tests/`, `docs/`.
4. **Скелет приложения.** `main.py` (FastAPI + `/ping`), `app/core/config.py` (pydantic-settings),
   `.env.example`, `.gitignore`, `requirements.txt`.
5. **База знаний.** Исходный RTF постановления (2.96 МБ) распарсен скриптом
   `scripts/parse_rtf.py` → `knowledge_base/pp719/pp719_full.txt` + 16 секций-чанков
   в `knowledge_base/pp719/chunks/` (по разделам приложения: автомобилестроение,
   радиоэлектроника, медизделия, стройматериалы и т.д.). RTF в репо НЕ хранится (в `.gitignore`).
6. **Документация.** README.md, SETUP.md, WORK_ON_OTHER_PC.md, docs/V1_SPEC.md
   (детальная техспека V1), docs/BUDGET.md (смета по фазам).
7. **Проверка.** `GET /ping` → `{"status":"ok","app":"Навигатор ПП РФ №719","version":"0.5.0"}` — работает.

**Фаза V1 (RAG-навигатор, MVP) — сделано:**
- **Спринт 1 — инфраструктура:** Qdrant в Docker (:6333), `app/rag/embeddings.py` (e5-large, 1024d).
- **Спринт 2 — структуризация:** `scripts/structure_kb.py` (регулярки + DeepSeek JSON) →
  `knowledge_base/pp719/structured/*.json` — **29 разделов, 1347 продуктов**. Контроль качества
  `scripts/verify_structured.py` (галлюцинации/потери) → **чисто; XXIX ⚠ (пороги вариантов кранов, V2)**. Фикс парсера X
  (многоколоночные пороги), запись-методичка прозовых порогов. Ускорение `--workers` + прогресс-бар.
- **Спринт 3 — индексация:** `scripts/load_kb.py` → Qdrant (1357 точек, гибрид dense+sparse).
  `app/rag/sparse.py` — локальный BM25 (mmh3+Snowball, без скачивания), нормировка по длине.
  Кэш эмбеддингов `.emb_cache/`, 18 потоков CPU.
- **RAG-пайплайн:** `app/rag/retriever.py` (гибрид + буст по ОКПД2), `app/rag/pipeline.py`
  (поиск → DeepSeek → ответ с обязательной пометкой эксперта), промпт навигатора в `prompts.py`.
- **Навигатор + API:** `app/tools/navigator.py`, `POST /navigate` (`app/api/routes.py`+`schemas.py`).
- **Интерфейс:** `frontend/streamlit_app.py` (Streamlit MVP).
- **Петля обучения:** `knowledge_base/cases/` + `scripts/seed_cases.py` + коллекция
  `verified_cases` — подтверждённые экспертом кейсы идут в контекст с высшим приоритетом.
- **Документация запуска/теста:** `docs/LAUNCH.md`, `docs/TESTING.md`.

**Принятые технические решения:**
- **LLM:** DeepSeek V3 (`deepseek-chat`) — доступен из РФ, дёшев, понимает русский и юр. текст.
  Нужен для: (а) разовой структуризации базы знаний, (б) генерации ответов пользователю.
- **Embeddings:** `intfloat/multilingual-e5-large` — локально, бесплатно, хорош на русском.
- **Vector DB:** Qdrant в Docker (у пользователя есть права администратора, выбран
  production-путь, а не встроенный режим). Конфиг гибкий — потом переключится на серверный
  Qdrant сменой `QDRANT_URL`.
- **RAG:** рукописный (qdrant_client + sentence-transformers напрямую; LlamaIndex НЕ используется —
  RF-first, контроль над антигаллюцинациями). **Backend:** FastAPI. **Frontend MVP:** Streamlit
  (вытесняется веб-чатом на FastAPI в 1.0).
- **Поиск:** гибридный (dense e5 + sparse BM25 + RRF fusion) — чтобы точно ловить и
  смысловые описания, и коды ОКПД2.

## 3. РАЗВЁРТЫВАНИЕ (выполни эти шаги на новом ПК)

> Claude, проверь каждый шаг. Если что-то уже сделано — пропусти. Команды для Windows PowerShell.

### Шаг 0. Проверить инструменты
```powershell
git --version          # нужен Git
py -3 --version        # нужен Python 3.11+
docker --version       # нужен Docker Desktop (запущен!)
```
Если чего-то нет — сообщи пользователю ссылки: Git → git-scm.com, Python → python.org,
Docker Desktop → docker.com.

### Шаг 1. Виртуальное окружение и зависимости
```powershell
py -3 -m venv .venv
.venv\Scripts\pip install --only-binary :all: -r requirements.txt
```
> ⚠️ `sentence-transformers` тянет PyTorch (~2 ГБ) — установка может идти долго.
> Флаг `--only-binary :all:` обязателен (Python 3.11+ на Windows без C++ Build Tools).

### Шаг 2. Файл секретов
```powershell
copy .env.example .env
```
Затем попроси пользователя вставить `DEEPSEEK_API_KEY` (с platform.deepseek.com).
Без ключа Спринт 1 всё равно можно начать (эмбеддинги локальные), ключ нужен на Спринте 2.

### Шаг 3. Автопуш-хук (на новом ПК настраивается заново)
Хук пушит ТЕКУЩУЮ ветку (`HEAD`), а не жёстко `main` — модель веток `main`/`dev`/`prod`/`exp/*`
(рабочая ветка по умолчанию — `dev`; `exp/*` не пушим). Подробно — [docs/BRANCHING.md](docs/BRANCHING.md).
```powershell
Set-Content .git\hooks\post-commit "#!/bin/sh`nbranch=`$(git rev-parse --abbrev-ref HEAD)`ncase `"`$branch`" in exp/*) exit 0 ;; esac`ngit push origin HEAD"
```

### Шаг 4. Поднять Qdrant в Docker
```powershell
docker run -d --name qdrant -p 6333:6333 -v ${PWD}\qdrant_storage:/qdrant/storage qdrant/qdrant
```
Проверить: открыть http://localhost:6333/dashboard — должна открыться панель Qdrant.

### Шаг 5. Проверить что backend запускается
```powershell
.venv\Scripts\python main.py
```
Открыть http://localhost:8000/ping → ожидается `{"status":"ok","app":"Навигатор ПП РФ №719","version":"0.5.0"}`.
Остановить сервер (Ctrl+C) после проверки.

После всех шагов — окружение готово. Сообщи пользователю результат каждого шага.

> Чтобы поднять **весь продукт** (индексация в Qdrant + веб-чат мини-1.0), а не только `/ping`:
> `scripts/load_kb.py` (разово) → `scripts/seed_users.py --admin-password admin` → `python main.py`
> → вход на `http://localhost:8000` (`admin`/`admin`). Подробно — [docs/LAUNCH.md](docs/LAUNCH.md),
> Вариант A. Структурированная база уже в репозитории — повторно парсить через DeepSeek не нужно.
>
> ⚠️ Первый `load_kb.py` скачивает модель эмбеддингов **e5 (~2 ГБ)** с HuggingFace. На
> нестабильной сети / из РФ CDN рвётся — используй `hf_xet` (уже в requirements, чанковая
> докачка), зеркало `HF_ENDPOINT=https://hf-mirror.com` или ручную папку `models/` +
> `EMBEDDING_MODEL` в `.env`. Подробно — [SETUP.md](SETUP.md), Шаг 5.

## 4. СЛЕДУЮЩИЙ ШАГ — деплой и приёмка эксперта

**Движок 0.5.0 и продукт мини-1.0 (веб-чат) собраны** (см. [ROADMAP.md](ROADMAP.md) §1.0.2–1.0.3).
До полного `1.0` осталось два гейта: развернуть и пройти приёмку эксперта.

**Что делать дальше (по приоритету):**

1. **Деплой (1.0.5)** — `docker-compose` (app + Qdrant + БД) + `Dockerfile` + детерминированный
   провижнинг e5 + TLS/домен. Демо-хостинг — Yandex Cloud (грант). Это единственный крупный
   недостающий кусок инфраструктуры (Dockerfile/compose/CI ещё НЕ написаны).
2. **Поднять и проверить продукт локально** — по [docs/LAUNCH.md](docs/LAUNCH.md), Вариант A:
   Docker→Qdrant, `.env` с ключом, разово `scripts/load_kb.py` + `scripts/seed_users.py`, затем
   `python main.py` → вход на `http://localhost:8000`. Прогнать 2–3 запроса для самопроверки.
3. **Приёмка с экспертом** — по [docs/TESTING.md](docs/TESTING.md): 5–10 реальных кейсов,
   критерий ≥ 70%. Стартовый набор — `docs/test_cases.csv` / `docs/test_cases.md`
   (пересобрать: `scripts/run_test_cases.py`). Label-вопросы эксперту: краны/экскаваторы III↔VI, буровые VI↔XX.
4. **Петля обучения** — исправления эксперта → `knowledge_base/cases/*.json` →
   `scripts/seed_cases.py` → ответы начинают учитывать кейсы с приоритетом.
5. **Fast-follow после демо** — стриминг ответа, history-aware мультитёрн, полный корпус
   Правил реестра (сейчас — процедурный дефер). Валидатор/калькулятор — `2.0` (см. ROADMAP).

После любой завершённой задачи — обнови статусы в `ROADMAP.md` и сделай коммит (автопуш настроен).

## 5. Правила работы (важно соблюдать)

- **Стек только RF-доступный.** Никаких сервисов, недоступных из РФ. LLM — только DeepSeek.
- **ИИ = черновик, эксперт = вердикт.** Каждый ответ системы помечать дисклеймером.
- **Коммить осмысленными порциями.** Сообщения коммитов — на русском в стиле conventional
  commits (`feat(web): …`, `fix(rag): …`, `docs: …`), с трейлером `Co-Authored-By: …`.
- **Обновляй ROADMAP.md** при старте/завершении задач.
- **Документируй на русском** (проект для русскоязычной ТПП).
- **Windows PowerShell** — учитывай синтаксис (`$env:VAR`, не `$VAR`; кириллица в
  терминале может отображаться кракозябрами — это норма, на работу не влияет).
