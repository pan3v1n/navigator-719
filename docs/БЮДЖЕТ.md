# Бюджет проекта «Навигатор ПП РФ №719»

> Оценка стоимости реализации прототипа по фазам.
> Все суммы — ориентировочные, в рублях (API — пересчёт с USD по курсу ~90 ₽/$).
> Цены на API и хостинг проверять на актуальность — меняются.

---

## Главная мысль

На выбранном **RF-стеке операционные расходы минимальны**:
- **LLM (DeepSeek)** — один из самых дешёвых на рынке, копейки за прототип;
- **Embeddings (e5-large)** — работают локально, **бесплатно**;
- **Qdrant** — open source, **бесплатно**;
- **Данные (текст №719)** — публичные, **бесплатно**.

Основная статья затрат в коммерческой разработке — **труд разработчика**.
Но поскольку разработка ведётся **самостоятельно через Claude Code**,
реальные расходы «из кармана» сводятся к подписке на инструмент + копеечному API + хостингу.

Поэтому ниже — **две колонки**:
- 💻 **Своими силами** (вы + Claude Code) — реальные деньги, которые потратите;
- 👥 **Если нанимать команду** — рыночная оценка для бюджета/КП заказчику.

## Что влияет на разброс цен

**Труд (найм):** зависит от квалификации (middle ~250K vs senior ~450K ₽/мес),
формата (фриланс / студия / штат) и того, насколько «грязные» данные приложений к 719.

**API DeepSeek:** прототип почти бесплатен. Расходы вырастут при реальной нагрузке
(много пользователей × длинные документы). Снижается кэшированием контекста (DeepSeek
даёт скидку до 90% на повторный контекст).

**Хостинг:** прототип можно держать локально (0 ₽). Боевой сервер с запасом —
дороже. GPU нужен только при потоковом OCR/эмбеддингах в больших объёмах.

---

## Рекомендации по экономии

1. **Прототипы V1–V3 разрабатывать и тестировать локально** — платный сервер поднять
   только для демонстрации эксперту/заказчику. Экономия: весь хостинг на этапе разработки.
2. **Структуризацию базы знаний (V1) прогнать один раз**, результат закоммитить в репо —
   не платить за повторный парсинг.
3. **Кэширование контекста DeepSeek** — типовые части промпта кэшируются, снижая цену запросов.
4. **e5-large на CPU** для прототипа достаточно — не арендовать GPU раньше времени.
5. **Один VPS на все три фазы** — не плодить серверы, наращивать ресурсы по мере роста.
