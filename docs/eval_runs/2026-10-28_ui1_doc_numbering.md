# UI-1 #165 — пункты Приказа №52 в товарном ответе: своя нумерация и свои источники (28.10.2026)

**Дефект.** Смешанный вопрос (продукция + состав документов) получает в контекст блок пунктов Приказа ТПП РФ
№52, и этот блок нумеровался заново с `[1]`. Источники ответа строились как «позиции ИЛИ пункты», поэтому
пунктов в товарном ответе не было вовсе. Если модель ссылалась на пункт Приказа как `[1]`, кнопка `[1]` в
панели «Источник» открывала позицию приложения №1. Промпт велел ссылаться на пункты «п. 4.2.1», и защита
держалась только на дисциплине модели.

**Правка.**
- Пункты Приказа нумеруются продолжением позиций: `format_rules_context(…, start=len(hits)+1)`.
- План передаёт пункты в ответ: `_Plan.doc_points` → `Answer.rule_sources` (синхронный и потоковый ответ).
- Источники ответа = позиции + пункты (`chat._answer_sources`; чат, поток, гостевой режим).
- Промпт разрешает ссылаться на пункт его меткой `[N]`: «у пунктов Приказа свои метки, они идут ПОСЛЕ
  позиций». Номер пункта «п. 4.2.1» по-прежнему просит.
- У процедурного ответа позиций нет, его порядок источников прежний.
- Оракул `eval_completeness.cites_ok` считает источники как `hits + rule_sources`.

## Замер (живой DeepSeek)

Документные кейсы `EV21` (47–50), по 2 прогона, `limit=8`. Для каждой ссылки `[N]` проверялось, куда она
ведёт.

| кейс | маршрут | позиций / пунктов | ссылки |
|---|---|---|---|
| 47 | процедурный | 0 / 6 | `[1]…[6]` → пункты (как прежде) |
| 48 | товарный (смешанный) | 8 / 3 | `[1]` → позиция; `[9]`, `[10]`, `[11]` → пункты Приказа |
| 49 | товарный (смешанный) | 8 / 3 | `[1]` → позиция; `[9]`, `[10]`, `[11]` → пункты Приказа |
| 50 | процедурный | 0 / 6 | `[1]…[6]` → пункты (как прежде) |

**Критерий задачи выполнен.** Кнопок, ведущих на позицию сразу после «п. N.N», — 0 из 8 ответов. Модель стала
ссылаться на пункты Приказа их собственными метками `[9]…[11]`, и каждая метка открывает свой пункт.

Тесты: нумерация в контексте и порядок источников проверены через `_plan_answer` и `_answer_sources`, ответ
и поток — с подменённой LLM. Мутации «нумерация с 1» и «позиции ИЛИ пункты» пойманы. Заземление не менялось:
блок документов в него не входит (решение, записанное в `_plan_answer`).

## Ревью (субагент, 28.10)

HIGH нет. Полная батарея у ревьюера — 2051 OK.

**MED, исправлен.** Метрика EV4 (`eval_text_faithfulness`) сверяла утверждения со ссылкой `[N]` только с
заземлением позиций. Теперь модель ставит `[9]` на пункт Приказа, и такое утверждение выглядело бы выдумкой:
метрика штрафовала бы предписанное поведение. Утверждения, ссылающиеся только на номера после позиций, теперь
сверяются с текстом самих пунктов (из данных, не из рендера). Добавлен тест.

**LOW, исправлены:**
- в чате подпись «Ещё N позиций» считает по составу: позиции, пункты или источники;
- правило 3б промпта знает о номерах блока ДОКУМЕНТЫ;
- сторож по код-объектам: все эндпоинты строят источники через `_answer_sources`, мутация в гостевом поймана;
- обновлены устаревшие комментарии.

**LOW, осознанно оставлено.** Старый API `/navigate` отдаёт источниками только позиции. Он закрыт для тарифных
пользователей, и хуже не стало: раньше `[1]` вёл на чужую позицию.
