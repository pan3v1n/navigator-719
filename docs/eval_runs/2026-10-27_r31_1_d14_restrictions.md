# R31-1 #228 — узкие ограничения D14 на сравнимых score: все три ОСТАЮТСЯ, теперь с замером (27.10.2026)

**Вопрос.** `D14` #141 выпущен узким: (а) новых предков не добираем, если среди совпавших есть потомки;
(б) потомков новых уровней не добираем; (в) у широкого кода с потомками ярусов предка нет — первый по рангу.
Обоснованием служила НЕСРАВНИМОСТЬ score кандидатов из разных запросов к Qdrant (#179). С `R31` #179
score окна сравнимы — держатся ли ограничения сами по себе?

**Замер.** `scripts/eval_okpd2_climb.py` (EXACT_SEARCH, коллекции ed1031), база — `dev` после `R31`
(тот же прогон, что база `EV8-1`). Шумовой пол двух прогонов «до» (снят для `R31`): own 0/0/5, climb 0/0/0,
control 0/0/0. Сравнение — «починено / сломано / смена целевой без смены вердикта».

| Вариант | own | climb | control | Вердикт |
|---|---|---|---|---|
| А — добирать предков и при потомках | 0 / 0 / 4 | 0 / 0 / 1 | 0 / 0 / 1 | пользы нет, лишний запрос к Qdrant — **оставить ограничение** |
| В — при потомках ставить их выше предков | 0 / 0 / 5 | **0 / 10** / 2 | 0 / 0 / 1 | **отклонено** — все 10 «сломано» действительно хуже |

**Вариант А.** Случаи, из-за которых ограничение вводили, на сравнимых score отвечают верно и без него:
«Мониторы и проекторы» 26.40.34 → «Мониторы, не предназначенные …», «Насосы центробежные» 28.13.14 →
«Насосы центробежные …», «Шлюпки спасательные» 30.12.19.140 → «Шлюпки спасательные», «Препараты для
лечения ЖКТ» 21.20.10.110 → «Препараты лекарственные …». Но и пользы нет: смены — перестановки внутри
одного кода. Снимать ограничение — платить запросом без выигрыша.

**Вариант В** — 10 «сломано», поимённо (код вопроса → было → стало):
* «Марля» 13.20.44 → «Ткани текстильные» 13.2 → «Бинты марлевые медицинские» 13.20.44.120;

Ограничения (б) и (в) держатся на смысле, а не только на несравнимых score; вариант В это показал и для (б):
добор потомков новых уровней привёл бы в окно ровно таких кандидатов.
