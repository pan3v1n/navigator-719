# R40 #239 — порог `RELEVANCE_SOFT` 0.83 → 0.82: парный замер отказа (28.10.2026)

**Решение владельца 28.10.2026:** вариант Б из [отчёта 27.10](2026-10-27_r40_relevance_flag.md) — порог 0.82
после `--check-refusal`. Критерий: отказ на вопросах вне 719 при 0.82 не хуже, чем при 0.83; у пограничных
профильных отказов не больше.

**Данные.** Коллекции `pp719_ed1031` / `pp719_rules_ed1031` (корпус `dev`). Наборы — `eval_golden_negative.json`
(39 вне 719) и `eval_golden_borderline.json` (20 профильных с низким косинусом).

## Метод: платим только за полосу, где флаг зависит от порога

Вне полосы `0.82 ≤ dt1 < 0.83` флаг при обоих порогах одинаков. Промпт там тот же, и разница ответов — только
шум модели. Поэтому новый режим `eval_guard.py --mode band` берёт лишь вопросы полосы и гоняет каждый **парно**:
при 0.83 и при 0.82, по три раза. Пороги чередуются внутри вопроса.

Порог подменяется у модуля продукта (`pipeline.RELEVANCE_SOFT`). Флаг решает код продукта, а не его повтор в
скрипте. Платный режим не входит ни в `both`, ни в `guard`, это закреплено тестом.

В полосе 11 вопросов (6 вне 719, 5 профильных): 66 ответов DeepSeek плюс реранкер.

## Результат

| набор | порог | флаг | отказ по детектору | отказ по смыслу (прочитано) |
|---|---|---|---|---|
| вне 719 | 0.83 | 18 / 18 | 16 / 18 | **18 / 18** |
| вне 719 | 0.82 | 18 / 18 | 15 / 18 | **18 / 18** |
| профильные | 0.83 | 15 / 15 | 1 / 15 | 1 / 15 |
| профильные | 0.82 | **3 / 15** | **0 / 15** | 0 / 15 |

- **Вне 719 флаг остался у всех шести вопросов и при 0.82.** Его поднимает второй сигнал — класс ОКПД2 вне
  покрытия 719 (`scope.py`), а не косинус. Детектор отказа (`_refused`, по словам — класс `EV11` #92) пропустил
  три ответа. Все три прочитаны, и все три — отказы по смыслу: «это услуга, а не промышленная продукция»,
  «прямой позиции нет, путь — СТ-1».
- **Профильные.** Флаг 15 → 3: остался только «гироазимут», его поднимает класс ОКПД2. Отказ 1 → 0: это были
  «прицепы для легковых автомобилей».
  - «Теплообменники» при 0.83 в двух прогонах из трёх просили код. При 0.82 сразу дают целевую позицию
    28.25.11.110 с требованиями.
- Незаземлённых чисел 0 во всех 66 ответах.
- ⚠ Строки «флаг при 0.83» (18 / 18 и 15 / 15) верны по построению, это не измерение: вся полоса ниже 0.83,
  совпадений по коду и кейсов у этих вопросов нет. Измерение — строки при 0.82 и столбец отказа.

**Критерий владельца выполнен:** отказ вне 719 не хуже (18 / 18 по смыслу при обоих порогах), отказов у
профильных не больше (1 → 0).

## Цена (видна в тех же ответах)

Без флага модель увереннее подаёт слабое совпадение поиска:

- **«Оборудование радиодоступа WEP-3ax»** (точка доступа Wi-Fi). Ответ берёт позицию «оборудование для
  управления … конференц-связи (кодек АКС, ВКС)» 26.30.23.142: при 0.83 — 2 из 3, при 0.82 — 3 из 3. Оба раза с
  пометкой «предварительно, проверьте».
  - Ближе по смыслу позиции IX/51 и IX/46. Это проблема поиска, а не порога: при 0.83 флаг тот же выбор не
    останавливал.
- **«Пластичная высокотемпературная смазка».** При 0.82 в одном прогоне из трёх ответ даёт требования и баллы
  позиции «перфторуглеродная смазка КСТ». Оговорки в ответе: «важно, чтобы ваша смазка была именно КСТ»,
  «предварительно, проверьте», просьба подтвердить наименование. Числа заземлены.
