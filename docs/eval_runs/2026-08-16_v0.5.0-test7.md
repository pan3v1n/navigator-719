| **Полнота ответа** | Метрики нет. Значит, пара «faithfulness ↔ полнота» разомкнута: рост faithfulness до 1.00 формально мог бы быть и «научился молчать». Косвенно опровергается ростом числа приводимых чисел (368–451 на 42 ответа) |
| **Ложный отказ на in-scope** | Нет набора пограничных in-scope. Отказы измерены только на негативах |
| **Вклад петли обучения** | Кейсы выключены на всём прогоне (по гайду). Отдельный дельта-прогон с включёнными не делался |
| **Нагрузка 10/25/50** | Боевая машина, открытая волна |
| **Latency до первого токена** | Замер шёл без стриминга |

## Решение

**Откат не требуется.** Версия `v0.5.0-test7` на бою по всем измеримым метрикам не хуже
предшественника, а по faithfulness — лучше (0.98 → 1.00 в трёх прогонах).

Принято как известный долг:

1. **Guard ослаб** — 5 из 36 негативов проходят порог. Не блокирует: полный пайплайн отказал
   36/36. Перекалибровку делать **после** волны и обязательно в паре с замером ложных отказов.
2. **Детерминизм 0.80** — эксперт может увидеть разные наборы баллов по одной позиции.
   Числа при этом заземлены всегда.
3. **Перефраз 0.808** — точная позиция по описанию своими словами находится в 4 случаях из 5;
   раздел — в 97 %.

Отдельно: **прогон на боевой машине занимает оба ядра на ~40 минут** (уровень 1). Ответ
пользователю конкурирует с замером за те же ядра, поэтому во время живой волны так делать нельзя —
для этого есть `scripts/eval_env.py` (инстанс из снапшотов). Наблюдённые снаружи таймауты `/ping`
к этому отношения не имеют — см. поправку в разделе «Новые дефекты», это канал, а не сервис.
