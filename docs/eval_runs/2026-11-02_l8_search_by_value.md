# Готовые команды: поиск по шаблону или по значению поля (`L8-1` #153)

Снято 02.11.2026 на ветке `feat/l8-1-commands`. Локальный Qdrant, коллекции `pp719_ed1031` и `pp719_rules_ed1031`, модель
e5 локально, реранкер и LLM не участвовали. Найдено ревью, замер повторён на своей выборке.

**Вывод.** Текст шаблона в поиске и в гейте релевантности ухудшает выдачу. У команд с полем поиск получает значение,
модель получает собранный запрос целиком. Исключение — `st1`: значение там голый код ТН ВЭД.

99 позиций `eval_paraphrases.json`, окно 8. В ячейке: r@1 / r@8 / сколько запросов получили флаг низкой релевантности.

| Разговорная формулировка 2 | 0.66 / 0.90 / 11 | 0.54 / 0.82 / 12 | 0.46 / 0.84 / 14 | 0.56 / 0.89 / 10 | 0.58 / 0.88 / 34 |
| Точное наименование | 0.92 / 1.00 / 10 | 0.88 / 0.97 / 9 | 0.86 / 0.97 / 15 | 0.91 / 1.00 / 10 | 0.89 / 1.00 / 18 |

Вне сферы, 39 запросов `eval_golden_negative.json`, сколько получили флаг:

| Прямой ввод | `req` | `parts` | `ops` | `points` |
|---|---|---|---|---|
| 38 | 30 | 21 | 35 | 39 |

Что это значит для ответа:

* нужная позиция чаще выпадает из окна, и реранкер её не вернёт;
* у `points` ложный флаг растёт почти вдвое и больше, а при флаге модель не выдаёт баллы, то есть команда «Баллы и порог»
  чаще отвечала бы без баллов;
* у `parts` флаг теряется на 17 запросах вне сферы из 39: продукция вне приложения получала бы уверенный ответ.

После правки поиск товарной команды получает то же значение, что и прямой ввод, поэтому её выдача совпадает с колонкой
«Прямой ввод». Это проверяет `tests/test_l8_commands.py`, `TestSearchByValue`.

## «Пункт простым языком»

По 40 случайных записей, поиск процедурной ветки: тема запроса, `search_rules`, окно `RULES_TOP_K`.

| Что указано в поле | Только значение: r@1 / окно | Весь шаблон: r@1 / окно |
|---|---|---|
| Сноска, `сноска <47>` | 1.00 / 1.00 | 1.00 / 1.00 |
| Пункт Правил, `пункт 32 Правил реестра` | 0.20 / 0.60 | 0.12 / 0.30 |
| Пункт Приказа, `пункт 12 Приказа ТПП РФ №52` | 0.00 / 0.03 | 0.00 / 0.03 |

Команда переведена на поиск по значению. ⚠ **Пункт Приказа №52 по номеру поиск почти не находит ни так, ни так.** Это не
регрессия: такой же вопрос, набранный руками, даёт то же самое. Номер не несёт смысла для поиска, а нумерация у приложений
Приказа повторяется. Надёжное решение — точный поиск записи по номеру и документу, отдельной задачей.

Значения-коды ОКПД2 (там работает буст по коду), итог с реранкером, ответы модели.
