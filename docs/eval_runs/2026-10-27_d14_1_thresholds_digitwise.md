# D14-1 #176 — поразрядная иерархия ОКПД2 в порогах: ОТКЛОНЕНО замером (27.10.2026)

**Вопрос.** `D14` #141 перевёл сопоставление «код вопроса → позиция» на поразрядную иерархию ОКПД2.
Соседняя логика — `thresholds._code_applies` (строка примечания → позиция) — осталась посегментной.
Переводить ли и её?

**Замер.** На `dev` + `D20` #225 + `D21` #230: `_code_applies` подменён поразрядным правилом в памяти
(`okpd2_ref.okpd2_key`, предок или равен), оба поиска порога — по всем 1573 позициям корпуса. Для каждой
изменившейся позиции напечатана строка примечания, которая дала бы ей порог, и сверена с
первоисточником (`chunks/130_PRIMECHANIYA_prilozheniya.txt`).

**Итог: общий +17 / 0 / −2, закупочный +4 / 0 / 0. Верных приобретений — 1–2 из 21, обе потери — неверные.**
Перевод отклонён: правило остаётся посегментным. Узкий случай «подкод категории + дословно то же имя»
уже закрыт `_subcode_of_group`.

## Почему так

Строки примечаний с кодом «…YZ0» или короткой группировкой почти всегда называют конкретное изделие
(«Блоки управления АБС», «Части компрессоров», «роторные управляемые системы»), а не всю ветку ОКПД2. В
поиске позиции (`D14`) подъём к группировке безопасен: целевой становится позиция-группировка, и модель
видит её наименование. В пороге подъём отдаёт ЧИСЛО чужого изделия без его имени — гард заземлённости и
эксперт подмены не видят. Это ровно класс, против которого стоит `_code_applies` (R8).

**Сторож:** `tests/test_d14_1_threshold_hierarchy.py` — четыре представительных случая (XXV/1, VI/26,
XIX/16, IX/114) остаются без чужого порога и при своём.
