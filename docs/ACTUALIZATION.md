## Переиспользуемый процесс (для любой новой редакции)

1. **Положить новый RTF** в корень (тот же источник, что и текущий — КонсультантПлюс, cp1251).
2. **Сверка (не мутирует базу):**
   ```bash
   PYTHONUTF8=1 .venv/Scripts/python.exe scripts/diff_edition.py --new-rtf "<новый>.rtf"
   ```
   Даёт: новые постановления, добавленные/удалённые позиции, -/+ по разделам, `full_diff.txt`.
3. **Понять дельту** по `full_diff.txt`: отделить **реальные правки** (новые позиции, изменённые
   баллы/пороги/операции) от **шума реэкспорта** (переносы `|`, «стран-членов»→«стран - членов»).
4. **Обновить исходник:** заменить `knowledge_base/pp719/pp719_full.txt` новым текстом
   (`scratchpad/edition_diff/pp719_new_full.txt`) → `python scripts/rechunk_appendix.py`
   (регенерит `chunks/*.txt`).
5. **Перепарсить ТОЛЬКО затронутые разделы** (остальные не трогать — DeepSeek недетерминирован,
   лишний перепарс = churn):
   ```bash
   PYTHONUTF8=1 .venv/Scripts/python.exe scripts/structure_kb.py --section <ROMAN>
   ```
6. **Проверить:** `verify_structured.py` (потери состава/баллов) + `reconcile_kb.py` (сверка по
   кодам исходник→JSON). ⚠ пайп-таблицы порогов в примечаниях парсер может принять за продукты.
7. **Реиндексировать:** поднять Qdrant (порт **6533** локально) → `python scripts/load_kb.py`
   (реиндекс дефолтом = **F1 identity-эмбеддинг**, НЕ `--full-text`).
8. **Замер без регресса:** `eval_retrieval.py` (recall@1 ~0.972) + `eval_answers.py` (faithfulness).
9. Обновить дату/редакцию в доках; на VM приедет при следующем редеплое (тома данных
   пересобираются из свежих JSON; юзер стартует VM в консоли, IP сменится).
