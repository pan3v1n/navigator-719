Предприятие описывает продукцию словами или кодом ОКПД2 — система находит применимую позицию
приложения к ПП №719, показывает требования к локализации, операции с баллами и порог **дословно
из первоисточника**, формирует перечень подтверждающих документов и отвечает на процедурные
вопросы о реестре, ГИСП и сертификате СТ-1. Всё — со ссылками на раздел, пункт и документ.

Заказчик — **Курская торгово-промышленная палата**. Цель — снять с экспертов рутинный поиск по
нормативному тексту и ускорить прохождение процедуры для предприятий.

> ⚠️ **Главный принцип: ИИ — черновик, эксперт — вердикт.** Ответ системы — предварительный
> анализ. Окончательное решение всегда принимает уполномоченный эксперт ТПП. Пометка стоит в
> интерфейсе и в каждой выгрузке диалога.

## Как это работает

RAG собран **вручную**, без фреймворка: `qdrant_client` + `sentence-transformers` напрямую. Это
осознанный выбор под условия проекта — RF-first, нестабильная сеть, полный контроль над
анти-галлюцинационным контуром. Подробный разбор — [docs/RAG_EXPLAINED.md](docs/RAG_EXPLAINED.md).

```
  Вопрос пользователя  (+ история диалога, якорь-код ОКПД2)
          │
          ▼
  ┌─ Детерминированные гейты ───────────────────────────────────────────────┐
  │  приветствие / «что умеешь»  ·  прямой перевод ТН ВЭД↔ОКПД2              │
  │  процедурный интент  ·  вне сферы 719 (по классу ОКПД2 и по сходству)   │
  └───────────────┬─────────────────────────────────┬────────────────────────┘
                  │ товарный вопрос                  │ процедурный вопрос
                  ▼                                  ▼
  ┌─ Коллекция pp719 (1377) ────────┐   ┌─ Коллекция pp719_rules (757) ─────┐
  │  dense e5-large + sparse BM25   │   │  тот же гибрид + тема вопроса      │
  │  RRF-слияние + буст по ОКПД2    │   │  квота окна по документам          │
  │  наследование требований группы │   │  иерархия юридической силы         │
  │  пороги из примечаний           │   │  справочник документов (К15)       │
  │  LLM-реранк, если кода нет      │   │  условия Перечня СТ-1              │
  └───────────────┬─────────────────┘   └──────────────────┬─────────────────┘
                  │  + кейсы эксперта (verified_cases)      │
                  ▼                                         ▼
  ┌─ DeepSeek (deepseek-chat) — ответ СТРОГО по контексту ──────────────────┐
  │  позиция · требования и баллы · порог · источники [N] · что уточнить    │
  └───────────────┬──────────────────────────────────────────────────────────┘
                  ▼
  ┌─ Постпроверка ──────────────────────────────────────────────────────────┐
  │  каждое число заземлено в контексте  ·  документ есть в закрытом перечне │
  │  подпись источника  ·  пометка «предварительный анализ» в выгрузке       │
  └──────────────────────────────────────────────────────────────────────────┘
```

Полный маршрут запроса с указанием, где в коде живёт каждый шаг, —
[docs/PRODUCT_SPEC.md §7](docs/PRODUCT_SPEC.md).

## База знаний

Состав корпуса задаётся **манифестом** [`knowledge_base/manifest.yaml`](knowledge_base/manifest.yaml):
у каждого документа паспорт (орган, юридическая сила, статус, срок действия, редакция). Загрузчик
читает манифест, а не хардкод путей; утратившие силу документы отсекаются и при индексации,
и на каждом запросе.

| Коллекция | Точек | Что внутри |
|---|---|---|
| `pp719` | 1377 | Приложение к ПП №719: 29 разделов, ~1370 видов продукции, требования, баллы, пороги, сноски |
| `pp719_rules` | 757 | Тело постановления · Правила ведения реестра · Приказ ТПП РФ №52 · Методрекомендации ТПП · Соглашение СНГ о происхождении · Приказ ТПП РФ №14 (СТ-1) · Положение об экспертизе происхождения (приказ №49) · FAQ ГИСП |
| `verified_cases` | 12 | Верифицированные экспертом кейсы — петля обучения |

Справочники без сети: ОКПД2, переходные ключи ТН ВЭД ↔ ОКПД2, условия Перечня СТ-1
(`knowledge_base/classifiers/`). Редакция ПП №719 — от 01.07.2026.

## Измеренное качество

Замеры идут по протоколу [EVAL_GUIDE.md](EVAL_GUIDE.md) уровнями от дешёвых к дорогим, каждая
метрика — в трёх прогонах, база сравнения обновляется только на релизном теге.

| Метрика | Значение |
|---|---|
| recall@1 / MRR / recall@10 (товарная ось, без реранкера) | **0.944** · 0.971 · 1.000 |
| Позиции-невидимки (нет в top-10) | **0** |
| Faithfulness — числа в ответе заземлены в контексте | **1.00**, три прогона подряд |
| Утечки чисел чужих позиций в ответ | **0** из 200 прогонов |
| Отказ вне сферы 719 | **4 / 4** |
| Атрибуция@1 первого источника (процедурная ось) | **0.96** |
| Условие Перечня СТ-1 найдено (К14) | **1.00** |
| Latency p50 / стоимость ответа | ≈ 8 с · ≈ 0.34 ₽ |

Последний полный прогон — [docs/eval_runs/2026-08-25_test17_full.md](docs/eval_runs/2026-08-25_test17_full.md),
база сравнения — [docs/eval_baseline/](docs/eval_baseline/).

**Приёмка заказчиком.** Региональный тест 17 ТПП (июль 2026, 470 вопросов) дал **33 % при гейте
≥ 70 %**. Причина диагностирована: потолок задавала полнота данных, а не пайплайн — позиций без
требований было 26 % корпуса, стало 0.8 %; расхождений баллов с первоисточником 7 → 0. Повторный
замер — по протоколу [docs/WAVE3_PROTOCOL.md](docs/WAVE3_PROTOCOL.md). Отчёты заказчику —
[REPORT_JULY_2026.md](docs/REPORT_JULY_2026.md), [REPORT_AUGUST_2026.md](docs/REPORT_AUGUST_2026.md).

## Быстрый старт

Нужны Python 3.12, Docker и ключ DeepSeek с [platform.deepseek.com](https://platform.deepseek.com).

```bash
git clone https://github.com/pan3v1n/navigator-719.git
cd navigator-719
python -m venv .venv && source .venv/bin/activate     # Windows: py -3 -m venv .venv && .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                                   # вписать DEEPSEEK_API_KEY и SESSION_SECRET
```

```bash
# 1) Qdrant и индексация базы знаний (разово)
docker run -d --name qdrant --restart unless-stopped -p 6333:6333 -v qdrant_storage:/qdrant/storage qdrant/qdrant
python scripts/load_kb.py          # приложение 719 → pp719
python scripts/load_rules_kb.py    # процедурные нормы → pp719_rules
python scripts/seed_cases.py       # кейсы эксперта → verified_cases

# 2) Пользователи и запуск
python scripts/seed_users.py       # печатает сгенерированные пароли в консоль
python main.py                     # → http://localhost:8000
```

Или одной командой на сервере: `docker compose up -d --build` (см. [docs/DEPLOY.md](docs/DEPLOY.md)).

> 💡 При первом `load_kb.py` с HuggingFace скачивается модель эмбеддингов `multilingual-e5-large`
> (~2 ГБ). На нестабильной сети: `hf_xet` уже в зависимостях, есть зеркало
> `HF_ENDPOINT=https://hf-mirror.com`, либо положите модель в `models/` и укажите путь в
> `EMBEDDING_MODEL`. Подробно — [SETUP.md](SETUP.md), шаг 5.

Ранний Streamlit-прототип (`frontend/streamlit_app.py`) вытеснен веб-чатом; его зависимости
вынесены в `requirements-dev.txt`.

## Конфигурация

Все настройки — в `.env`; полный список с пояснениями в [`.env.example`](.env.example), его
соответствие коду проверяет тест. Ключевые переменные:

| Переменная | Назначение |
|---|---|
| `DEEPSEEK_API_KEY` | ключ DeepSeek — единственный внешний вызов сервиса |
| `SESSION_SECRET` | подпись сессионных кук; в `APP_ENV=production` с дефолтным значением приложение **не стартует** |
| `QDRANT_URL` · `QDRANT_COLLECTION` · `QDRANT_RULES_COLLECTION` · `QDRANT_CASES_COLLECTION` | адрес и имена трёх коллекций |
| `EMBEDDING_MODEL` | имя модели на HuggingFace или абсолютный путь к локальной папке |
| `RERANK_ENABLED` · `CASE_RELEVANCE_MIN` | LLM-реранк и порог релевантности кейсов эксперта |
| `PROCEDURAL_ANSWER_FROM_RULES` | процедурные вопросы отвечаются по корпусу норм (иначе — честный дефер) |
| `RATE_LIMIT_CHAT_PER_MIN` · `RATE_LIMIT_LOGIN_PER_MIN` | лимиты на пользователя |
| `APP_DB_URL` · `LOG_FILE` | SQLite приложения и файловый лог с ротацией |
| `RELEASE_TAG` | тег выкатки для пометки версии в интерфейсе и в `/ping` |

## API

```bash
curl -X POST http://localhost:8000/navigate \
     -H "Content-Type: application/json" \
     -d '{"query":"производим прицепы для легковых авто","okpd2":"29.20.23"}'
```

Ответ: `answer` (разбор), `sources` (позиции с разделом, кодами, операциями и якорем),
`checklist` (документы), `disclaimer`. Интерактивная схема — `/docs`.

| Маршрут | Назначение |
|---|---|
| `POST /navigate` | навигатор без сессии — для интеграций |
| `POST /api/chat` · `POST /api/chat/stream` | чат с историей; стриминг по SSE |
| `GET /api/conversations`, `…/{id}`, `…/{id}/export` | список, содержимое и выгрузка диалога |
| `POST /api/feedback` | оценка ответа экспертом |
| `GET /api/export` · `GET /api/admin/export` | выгрузка своих диалогов / всех (админ) |
| `GET /login` · `/chat` · `/profile` · `/admin` | страницы веб-интерфейса |
| `GET /ping` | healthcheck, отдаёт тег релиза |

## Тесты и замеры

```bash
python -m unittest discover -s tests      # 1317 тестов, офлайн, без Qdrant и без ключа
```

CI (GitHub Actions) гоняет батарею на каждый push и PR; тест, которому понадобились Qdrant или
ключ, падает — и это правильный сигнал. Каждый предохранитель проверяется мутацией: правка
отменяется, названный тест обязан покраснеть.

Замеры качества — скриптами `scripts/eval_*.py` по уровням [EVAL_GUIDE.md](EVAL_GUIDE.md):
целостность корпуса → ретрив → ответ (платно) → устойчивость → надёжность и стоимость. Отчёты
прогонов — [docs/eval_runs/](docs/eval_runs/).

## Выкатка

Одна VM, `docker compose`: контейнер приложения (FastAPI + e5) и контейнер Qdrant, тома для
модели, БД и коллекций. Выкатка — эталонным скриптом
[`scripts/deploy/deploy.sh`](scripts/deploy/README.md) с профилем релиза: бэкап БД до всего,
сверка маркеров пакета, гейт CI, общие проверки рантайма на каждом релизе и релизные проверки,
сухой прогон без касания боя. Переиндексация корпуса при добавлении документа — **полная**
(`avgdl` BM25 запекается в вектор каждой точки).

Ветки: `dev` (рабочая) → PR в `main` (стабильная, тег `vX.Y.Z-testN`) → `prod` (ровно то, что
крутится на сервере). Подробно — [docs/BRANCHING.md](docs/BRANCHING.md), [docs/DEPLOY.md](docs/DEPLOY.md).

## Принципы

- **AI — черновик, эксперт — вердикт.** Пометка о предварительном характере — в интерфейсе и в каждой выгрузке.
- **Ответ строго по базе.** Числа, которых нет в контексте, помечаются; документы вне закрытого перечня не утверждаются.
- **Петля обучения.** Исправления эксперта попадают в `knowledge_base/cases/` и учитываются без дообучения модели.
- **Замер вместо заявления.** Каждая правка ретрива или промпта измеряется по протоколу в трёх прогонах.
- **RF-first и self-hosted.** Единственный внешний вызов — DeepSeek API; данные остаются внутри ТПП (152-ФЗ).
- **Portable.** Весь контекст в репозитории — работу можно продолжить с любого ПК.

содержат персональные данные и в репозиторий не попадают (152-ФЗ).
