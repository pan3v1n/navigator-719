# Навигатор ПП РФ №719 — Проектная база для Claude Code

## Контекст проекта
Сервис для Курской торгово-промышленной палаты (ТПП).
Помогает предприятиям разобраться в требованиях **Постановления Правительства РФ №719**
о подтверждении производства промышленной продукции на территории РФ (критерии локализации,
балльная система, документальное подтверждение).

**Заказчик**: Курская ТПП  
**Цель**: снизить нагрузку на экспертов ТПП, ускорить прохождение процедуры для предприятий  
**Ограничение**: ИИ — черновик, финальный вердикт всегда за экспертом ТПП

## Стек (только RF-доступные инструменты)

| Слой | Технология | Причина выбора |
|---|---|---|
| LLM | DeepSeek V3 (`deepseek-chat`) | API доступен из РФ, дёшево, качественно |
| Embeddings | `sentence-transformers` (локально) | Без внешних API, бесплатно |
| Vector DB | Qdrant (self-hosted Docker) | Open source, РФ-доступен, production-ready |
| RAG | **рукописный** (прямо на `qdrant_client` + `sentence-transformers`) | Полный контроль, минимум зависимостей при рваной сети; LlamaIndex НЕ используется (кандидат на стадию 4 — parent/child, см. ниже) |
| Backend | FastAPI (Python 3.11+) | Стандарт, async, хорошая документация |
| База данных | SQLite (dev) → PostgreSQL (prod) | Простой старт, масштабируется |
| Frontend 1.0 | Лёгкий веб-фронт (HTML/JS) на FastAPI | Мультиюзер-чат + роли `user`/`expert`/`admin`, без React-сборки |
| Frontend (ранний MVP) | Streamlit (форма) | Навигатор-MVP; в 1.0 вытесняется чатом |
| Frontend Prod | React + Vite (2.0+) | Только если подтвердит ценность |
| Хостинг | Selectel / Timeweb / Yandex Cloud | РФ-юрисдикция, ФЗ-152 |
| Telegram UI | aiogram 3 (опционально) | Быстрый доступ для экспертов ТПП |

> **RAG реализован вручную, без фреймворка.** Гибрид-поиск собран напрямую: dense — `e5-large`
> (`sentence-transformers`, локально), sparse — **локальный BM25** (`app/rag/sparse.py`, mmh3 +
> Snowball, без скачивания моделей), слияние — нативный `FusionQuery(RRF)` Qdrant + доменный
> ОКПД2-буст. Это осознанный выбор под условия проекта (RF-first, рваная сеть DPI/zapret, контроль
> над анти-галлюцинациями), а не недоработка. **LlamaIndex не подключён**; его рассматриваем точечно
> только на стадии 4 (parent/child auto-merging), если упрёмся в усечение операций. Полный разбор
> архитектуры и план улучшений — [docs/RAG_EXPLAINED.md](docs/RAG_EXPLAINED.md) и раздел RAG в
> [docs/IDEAS.md](docs/IDEAS.md).

## Секреты (никогда не коммитить)
Файл `.env` в `.gitignore`. Копировать из `.env.example`.
- `DEEPSEEK_API_KEY` — от platform.deepseek.com
- `DATABASE_URL` — строка подключения к БД
- `QDRANT_URL` — адрес Qdrant (локально: http://localhost:6333)
- `SESSION_SECRET` — подпись сессионных кук; в проде приложение НЕ стартует с дефолтным

> Полный список настроек с пояснениями — в `.env.example`; он сверен с `app/core/config.Settings`
> (расхождение ловит тест `TestEnvExampleMatchesSettings`). Telegram-интерфейс из планов не ушёл,
> но кода под него нет — переменной в конфиге тоже.

> **Модель эмбеддингов (provisioning).** По умолчанию e5-large качается с HuggingFace при
> первом `load_kb`. На нестабильной сети / из РФ CDN рвётся — решения: `hf_xet` (уже в
> requirements, чанковая докачка), зеркало `HF_ENDPOINT=https://hf-mirror.com`, либо ручная
> папка `models/` + абсолютный путь в `EMBEDDING_MODEL`. Подробно — `SETUP.md` (Шаг 5),
> бэклог по теме — `docs/IDEAS.md` (раздел Инфра). Сама модель и `models/` — в `.gitignore`.

## Персональные данные (152-ФЗ) — никогда в git

Выгрузки с боевого сервера (`navigator-export/`, дампы `*.db`, `dump_tables.json`, таблицы выданных
доступов) содержат **ПДн реальных пользователей региональных ТПП**: диалоги, ФИО, регион, Telegram.
Они в `.gitignore` — и это не «на всякий случай»: git-история необратима, приватность репозитория
её не отменяет.

**Правило:** выгрузки хранить **вне рабочего дерева репозитория** (напр. `D:\navigator-export\`),
в репо — только агрегаты и обезличенный анализ (как `docs/REPORT_JULY_2026.md`). Перед любым
`git add -A` проверять `git status`. История проверена 2026-08-10 — вхождений нет.

## Граф знаний проекта (graphify)

**При любом вопросе по архитектуре, коду или связям внутри проекта — сначала обращайся к графу,
а не грепай файлы вслепую.** Граф построен инструментом [graphify](https://github.com/safishamsi/graphify)
и лежит в `graphify-out/`.

Что внутри графа (полная пересборка **2026-08-10**): **1586 узлов, 3311 рёбер, 108 сообществ**.
- **код** — tree-sitter AST по 115 файлам (`.py` + `chat.js`): 794 узла;
- **документация проекта** — 47 файлов (`docs/`, `README`, `ROADMAP`, `CLAUDE.md`, `V1_SPEC` и др.),
  извлечение LLM: 532 узла + 260 узлов-обоснований;
- **мосты doc→code — 625 рёбер (19 % всех связей)**: концепт из документа → конкретная функция или
  класс. Ради них граф и строится: «где реализовано то, что описано в ТЗ».

⚠️ **`knowledge_base/` из графа исключён намеренно** (40 файлов, 10.9 МБ). Текста самого ПП №719 в
графе нет — он живёт в Qdrant для RAG-поиска; граф про устройство *системы*, а не регламента.
Индексация корпуса залила бы граф сущностями постановления и стоила бы в ~15 раз дороже.

Как пользоваться (в порядке предпочтения):
1. Прочитать `graphify-out/GRAPH_REPORT.md` — god-узлы (ядро архитектуры), сообщества,
   surprising connections, готовые вопросы.
2. `graphify query "<вопрос>"` — обход графа по вопросу (нужен установленный пакет `graphifyy`).
3. Открыть `graphify-out/graph.html` в браузере — визуально (мосты doc↔code видно глазами).

⚠️ **Граф локальный — в репозитории его НЕТ** (`graphify-out/` в `.gitignore`). На свежем клоне
его нужно пересобрать:
```bash
pip install graphifyy        # один раз, в Python с которым работает агент
# затем в Claude Code:
/graphify .
```
На **Windows** перед ручными вызовами graphify ставь `PYTHONUTF8=1 PYTHONIOENCODING=utf-8`
(в корпусе кириллица — иначе `UnicodeDecodeError`) и используй реальный Python, а не Store-заглушку `python3`.

### ⚠️ Windows-ловушка `.graphify_root` — из-за неё автообновление молчало 8 недель

Хук читает корень проекта из `graphify-out/.graphify_root`. Скилл записывает туда результат
`cd <path> && pwd`, а в Git Bash это **POSIX-путь** `/d/navigator-719`. Windows-Python понимает его
как `D:\d\navigator-719` — несуществующую папку (хук её же и создавал пустой). Итог: на каждом
коммите в лог падало «No code files found - nothing to rebuild», и граф не обновлялся с 17.06,
хотя `CLAUDE.md` обещал автообновление.

**Правильное содержимое файла — Windows-путь с прямыми слэшами:**
```
D:/navigator-719
```
Проверить, что автообновление живо:
```bash
cat graphify-out/.graphify_root                    # должен быть D:/navigator-719
tail -3 ~/.cache/graphify-rebuild.log              # после коммита — "Rebuilt: N nodes"
```
Если после `/graphify .` файл снова стал POSIX-путём — перезаписать вручную, скилл делает это
каждый раз.

### Как пересобирать полностью (со слоем документации)

Кодовый слой пересобирается сам на каждом коммите (post-commit hook), LLM не нужен.
Слой документации требует извлечения субагентами — прогон 2026-08-10 занял 8 параллельных
агентов на 47 файлов (754 КБ). Ключевые приёмы, без которых получается мусор:
1. **Исключить `knowledge_base/`** — иначе в граф уедет текст ПП №719 (10.9 МБ).
2. **Дать агентам индекс кодовых узлов** — выгрузить AST-узлы в `.graphify_code_index.tsv`
   (`id<TAB>label<TAB>файл`) и велеть искать в нём по grep. Без этого мосты doc→code
   получаются висячими: агент выдумывает идентификаторы, которых в графе нет.
   Результат прогона: 625 мостов, **0 висячих рёбер**.
3. **Делить порции по объёму, а не по числу файлов** — размеры отличаются в сто раз.

Результаты извлечения кэшируются (`graphify-out/cache/`, 47 файлов) — следующая пересборка
документации будет бесплатной, пока файлы не изменились.

## Ключевые принципы разработки

1. **AI — черновик, эксперт — вердикт.** Ответ системы — предварительный анализ, требующий
   проверки уполномоченным экспертом ТПП. **Где именно стоит пометка** (уточнено 2026-08-10,
   задача R3): в интерфейсе — постоянной строкой под полем ввода (`chat.html`), а не в теле
   каждого ответа (это осознанно убрано, правило 6 промпта навигатора: внутренний инструмент,
   повтор дисклеймера в каждом сообщении — шум); в **любой выгрузке** (`/api/export`,
   `/api/conversations/{id}/export`, `/api/admin/export`) — шапкой документа и подписью каждой
   реплики ассистента. Экспорт маркируется обязательно: именно он уносит ответ за пределы
   сервиса — заявителю, в переписку, в приложение к заявке.

2. **Петля обучения.** Ошибки, которые находит эксперт, фиксируются в `knowledge_base/cases/`
   и переиндексируются — точность растёт без дообучения модели.

3. **RF-first стек.** Никаких зависимостей от сервисов, заблокированных или недоступных в РФ.
   Все внешние API — только DeepSeek (работает из РФ напрямую).

4. **Portable dev environment.** Весь код в GitHub. CLAUDE.md содержит полный контекст.
   Любой Claude Code на любом ПК с доступом к репо может продолжить работу.

## Ветки и рабочий процесс

**Модель:** `prod` (развёрнуто на сервере — FF из main/dev при деплое) · `main` (стабильная, её
тестирует эксперт — теги `vX.Y`) · `dev` (интеграция, рабочая ветка по умолчанию) · `exp/<тема>`
(выбрасываемые эксперименты с моделями/UI/функционалом).
Поток: `exp/* → dev` (прямой merge) → `dev → main` (**через PR** + `/code-review`) → `main → prod`
(FF при деплое). Эксперименты изолируем через **git worktree** (своя папка, свой `.env`).
_(2026-07-02: main перемотан на dev, prod создан из dev — первый релиз-синк; см. docs/BRANCHING.md.)_

⚠️ В эксперименте задавай своё `QDRANT_COLLECTION` (напр. `pp719_exp_*`), иначе `load_kb.py`
затрёт рабочую `pp719`. Автопуш-хук пушит текущую ветку (`HEAD`), но **`exp/*` не пушит**.
Полностью — в **[docs/BRANCHING.md](docs/BRANCHING.md)**.

## Как продолжить работу на новом устройстве
```bash
git clone https://github.com/pan3v1n/navigator-719.git
cd navigator-719
py -3 -m venv .venv
.venv\Scripts\pip install -r requirements.txt
copy .env.example .env
# Заполнить .env секретами
# Запустить Qdrant: docker run -p 6333:6333 qdrant/qdrant
.venv\Scripts\python scripts/load_kb.py   # загрузить базу знаний
.venv\Scripts\python main.py              # запустить сервис
```
