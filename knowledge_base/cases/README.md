# Кейсы, подтверждённые экспертом Курской ТПП (петля обучения)

Здесь живут **проверенные экспертом** разъяснения и исправления. Они индексируются в
отдельную коллекцию Qdrant `verified_cases` и при поиске идут в контекст ответа с
**высшим приоритетом** — так точность растёт без дообучения модели (см. CLAUDE.md, принцип 2).

## Как добавить кейс

1. Создай файл `knowledge_base/cases/<краткое-имя>.json` (один кейс = один объект, либо
   массив объектов). Файлы, имя которых начинается с `_`, загрузчик **пропускает**
   (для шаблонов/черновиков — см. `_example.json`).
2. Запусти переиндексацию:
   ```
   .venv/Scripts/python.exe scripts/seed_cases.py
   ```
3. Готово — кейс участвует в поиске. Коммить файл в репозиторий.

## Схема кейса

| Поле | Обяз. | Описание |
|---|---|---|
| `query` | да | Как предприятие формулирует вопрос/ситуацию (по нему ищем похожие). |
| `expert_answer` | да | Проверенный экспертом ответ/разъяснение (идёт в контекст как эталон). |
| `okpd2` | нет | Код ОКПД2 продукции. |
| `section_roman` | нет | Раздел приложения к 719 (I, II, …). |
| `product_name` | нет | Наименование позиции. |
| `correction_of` | нет | Что AI ответил неверно (фиксируем ошибку для истории). |
| `tags` | нет | Метки (список строк). |
| `source` | нет | Кто и когда подтвердил (ФИО эксперта, дата). |

Текст для поиска = `query` + `product_name` + `expert_answer` + `okpd2`.
Полный объект кейса сохраняется в payload точки Qdrant.
